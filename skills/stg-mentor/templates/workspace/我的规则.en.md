# My Rules (我的规则)

> **This is your rules file, and it has the highest priority.**
> Every time the tutor takes over, it reads this **first**, then the framework defaults (`references/协议/00_导师协议.md` inside the skill).
> **Anything written here overrides the framework defaults.**
>
> You can: change any entry, delete what you don't want, add your own, write your own teaching preferences.
> Not sure how? Just tell the tutor "I want to change X to Y" — it will write it into this file.

> Chinese version: [`我的规则.md`](./我的规则.md)

---

## How to use it

**This file starts empty (everything is commented out) — empty means "use all framework defaults", and that's perfectly fine.**

To change something, **remove the `<!--` and `-->` around that line** (uncomment it) and set your value.

Three ways, pick any:

| Way | How |
|---|---|
| **Edit directly** | Edit this file, uncomment and change |
| **Say it out loud** | Tell the tutor "from now on give me only 1 question per round" → it writes it here |
| **Do nothing** | Keep everything commented = pure framework defaults |

**Example of uncommenting**:

```markdown
<!-- Before: this line is commented out, it does nothing -->
<!-- - Questions per round: 2 -->

<!-- After: it is live and overrides the framework default -->
- Questions per round: 1
```

## Priority (for the tutor)

**Rule priority, highest first**:

```
1. 我的学习/我的规则.md                ← highest, overrides everything below
2. What the student says right now     ← overrides everything below #3
3. 我的学习/00-学习档案.md 🚦           ← current progress (state, not a rule)
4. skill's references/协议/00_导师协议.md   ← framework defaults
5. skill's references/学科包/<subject>.md  ← that subject's assessment criteria
6. the rest of the skill's SKILL.md     ← framework entry point
```

**On conflict**: go down the list, the higher one wins.
**Not written here**: framework defaults apply.
**Written here**: this file wins, even against a framework default.

> **One exception**: if you wrote two entries that **contradict** each other, the tutor must **ask which one you want** rather than guess.

### Operating criteria

| Situation | What to do |
|---|---|
| Student says "from now on change it to X" | Write X into this file (**never** edit the skill's `references/协议/` — that is read-only framework) |
| Student says "I don't like Y" | Same — turn it into an explicit rule |
| This file is empty | Use framework defaults; **do not** proactively write anything into it |
| Two rules contradict each other | **Ask the student which one**, never pick for them |
| You want to suggest a rule | You may propose it, but only write it in with the student's consent |
